# NDAIB feedback runtime

This is a reader capability of the existing canonical reader builder, not an
editorial or publishing pipeline. `scripts/build_reader_bundle.py` generates
the public reader and a sibling `<destination>.runtime` directory. The registry
is derived from rendered canonical item/date attributes, including all media
items. Native Sites publication packages the same reader as `dist/client` and
the runtime entrypoint as `dist/server/index.js` under the existing ndaib ID.

The Site owns its D1 database. The legacy ratings Site, repository, and Command
Centers are not changed. Historical editorial files and original image files
are retained. Legacy feedback records remain with the legacy service; new
NDAIB feedback starts in its own database without fabricated imported totals.

Ratings and share/read events use immutable operation IDs to prevent retry
double-counting. Watchlist ballots use monotonically increasing revisions.
Comments are private, have no public read endpoint, and expired comments are
purged on comment writes. The editor can review them through the Site's owner
database tools. No email provider is configured: existing RSS and calendar
subscription methods remain available, and email signup stays hidden.

Schema migrations are generated by `npm run db:generate` and applied by Sites.
Never run schema creation in request handlers or edit applied migrations.
Run `node --test migration/reader-runtime/runtime.test.mjs` from the repository.
The SQLite adapter is used only by local QA, never by the production Worker.
